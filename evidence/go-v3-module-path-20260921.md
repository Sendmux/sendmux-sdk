## Why

`apidiff` against `go/v2.0.0` after the union member shims still lists two classes of change no alias or shim can cover (`evidence/v1-8-250-regen-20260921.md`, "Go release type: breaking"): the eight `Provider{Create,Update}BodyQuotasPer{Day,Hour,Minute,Second}.Nil<Union>1` member fields are removed (the member is the `ProviderQuotaRange` field) and five fields change from a `Nil…` wrapper to the plain canonical type. `628561d` (`fix(go)!`, BREAKING CHANGE footer) already makes release-please propose go 3.0.0 (PR #285, head `4c4d64e`, `go/go.mod` still `sendmux.ai/go/v2`). A Go major above 1 is part of the import path, so 3.0.0 must ship as `sendmux.ai/go/v3` (go.dev/ref/mod, "Major version suffixes"); this change-set moves the path and the shipped READMEs first, exactly as `dc01472` did for v1 → v2 (`go.mod`, imports, `scripts/generate-go.mjs`, `scripts/ci-consumers.mjs`, `release-please-config.json` `package-name`, README badge/install/table/migration section).

## Vanity import

`sendmux.ai/go/...` is served by `SITE_sendmux.ai/src/middleware.ts:9-19`: any request with `?go-get=1` receives `<meta name="go-import" content="sendmux.ai git https://github.com/Sendmux/sendmux-sdk">` before the trailing-slash redirect. The import prefix is `sendmux.ai`, so the Go tool maps `sendmux.ai/go/v3` to subdirectory `go` of that repository at tag `go/v3.0.0`, exactly as `sendmux.ai/go/v2` maps today (`Origin.Subdir go`, `Ref refs/tags/go/v2.0.0` above). Live probe: `https://sendmux.ai/go/v3?go-get=1` → HTTP 200 with the same meta tag as `/go/v2` and `/go` (`vanity-probe` in the L18 report). No site change is needed for v3.
